## xrep main vs hela 全链路压测对比（报告：.plannings/compare-2026-11-08/report.md）
- 用 git worktree 隔离 `hela:main` / `hela:design` 两份编译器，均以 release 构建。
  **构建 Odin 必须** `CXX=/usr/bin/clang++ LLVM_CONFIG=/opt/homebrew/opt/llvm@22/bin/llvm-config`
  （默认会误选 Homebrew LLVM 23，与 Xcode 26.5 SDK 的 libc++ 冲突报 `size_t`/`FP_ZERO` 未定义）。
- 四组隔离：A(main 源码+原版 Odin) / B(hela 源码+Hela 编译器) / C(main 源码+Hela 编译器，控制组) /
  D(hela 源码+原版 Odin，编译失败于 `#share`)。**C/A 端到端 0.99–1.07x、二进制仅 +16 B**
  → 差距来自 xrep 源码（ADR 0010–0013），不是编译器 codegen；编译器只在个别微循环
  （multi_match / bndm）给同一份 main 源码带来 1.1–1.5x。
- 25 个端到端场景 + 多轮 `--bench`：稀疏/无命中持平，密集/多模式 3.3–17x，
  `-i` 密集文本 470–525x（main 的 O(n²) 已知缺陷，非通用加速比），maxRSS −21…−42%；
  三组单测 / 78 golden / run2 34 / run3 56 全绿，25 场景输出等价。
- 发现并修 5 处测量问题：进度条帧污染等价校验、`/usr/bin/time` 10 ms 精度、
  计时未加 `-q`、只测 `-c` 偏袒 count-only、`--bench` 解析器把 A3/A5 同名 case 混算。
  补测（新增 3 轮 --bench + 6 场景 × 5 轮）结论稳定。
- micro `multi_ac` 0.49–0.56x 经 12 组诊断实验定为**编译产物布局敏感性**
  （非算法回归：独立程序 A/B/C 都 356 MB/s；端到端走 AC 的 S18/S19 B 快 3.59x），
  不改产品代码。`--contract` 的 1 个 `shared field without #atomic` 是提示计数，硬指标 0 冲突。
- 脚本与原始数据：`/private/tmp/xrep_compare/`（bin/corpus/logs/results.csv/summary.json/
  equivalence.json/recheck_summary.json + build_xrep.sh、bench_e2e.py、diag_*.py）。

# ADR 0011 — 并行多路归并（最小堆 + rank 精确切分）

日期：2026-11-07　分支：`hela`　状态：已实施

## 背景

ADR 0010（并发骨架换血）之后，稠密命中路径的瓶颈只剩一处：**单线程的多路归并**。

用 `XREP_PROFILE=1` 分解 64 MiB 稠密数据（命中密度 1/8 字节，8 388 670 条命中，
32 个分片列表）：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| workers（并行扫描） | 34.5 ms | 11 % |
| **merge（串行 K 路归并）** | **281.3 ms** | **82 %** |
| filter（区间过滤） | 21.3 ms | 6 % |

线程数 1 → 10 的端到端时间是 0.40 s → 0.34 s：几乎没有扩展，因为 82 % 的时间在
一段串行代码里。

旧实现每条输出都线性扫过全部列表的游标取最小者，复杂度 O(总命中数 × 列表数)。
列表数 = 分片数（64 MiB / 2 MiB = 32），于是 8.39 M × 32 ≈ **2.68 亿次**带分支的
比较。这是两个独立问题叠在一起：算法（N·K 而非 N·log K）与并行度（1 个线程）。

## 决定

### 1. 线性扫描 → 最小堆

堆里存**列表下标**而不是条目（条目 16 B，搬动它没有意义；取最小者只是读一次
`lists[i][cur[i]]`），比较键是 `(offset, 列表下标)`：

- `offset` 决定大小；
- 列表下标做平局键，用来**精确复刻**旧实现的顺序：旧的线性扫描用严格 `<`
  从左往右找最小，因此相等偏移时下标小的列表先出。

32 路时每条输出从 32 次比较降到 5 层下滤。

### 2. 单线程 → rank 精确切分的并行归并

各列表已排序，所以"全局第 T 条是哪个条目"**只由数据决定**，与谁在算无关。于是
可以把全局序切成 p 段，每段交给一个线程：

1. 二分出边界值 v：使 `Σ upper_bound(list_i, v) ≥ T` 的最小 v；
2. 按**列表下标从小到大**分配"偏移恰好等于 v"的条目，补足到恰好 T 条 ——
   这个顺序就是平局规则本身（下标小的先把 v 排空）。

切分带来三个直接后果：

- 每个分区的输出落在一个**已知的 rank 区间**里，可以直接写进最终数组的对应位置：
  输出只分配一次，不需要"各算一段再拼接"，也没有额外的拷贝；
- 输出与串行归并**逐条相同**，而且**与分区数无关**（换 `--threads` 不改结果）——
  这是 golden / `--dump` 能继续逐字节比对的前提；
- 各分区长度差不超过 1，天然负载均衡，不需要工作窃取。

`search.merge_split_starts` 里还有一条自检式恒等式：各列表游标之和必然等于
`total*part/p`。它若不成立，输出位置就会错位，所以单测直接断言它。

### 3. 分层：算法留 `search`，线程留 `engine`

`search/merge.odin` 不含任何线程代码（可被纯单测覆盖，含一个旧算法的逐字复刻
参照实现）；`engine/merge.odin` 只负责决定切几段、备内存、起线程、join。

### 4. 线程里零分配

`starts` / `scratch` / `out` / `jobs` / 线程句柄全部由主线程备好再传进线程。
原因见 ADR 0003：`odin test` 下主线程的分配器是 `mem.Tracking_Allocator`
（内部无锁 map），多线程同时分配会写坏它（实测 SIGBUS）。归并线程只写内存、
不申请内存，这条约束就不可能被踩到。线程入口仍然显式
`context = runtime.default_context()`，让"与创建者无关"成为契约而非巧合。

### 5. 输出数组不清零

`runtime.non_zero_make_slice` 代替 `make`：134 MB 的置零（约 7–10 ms）是纯浪费，
每个位置都必然会被 `merge_range` 写到。

### 6. 区间过滤：从"重新复制"改成"有序区间 + 原地收缩"

归并结果全局升序，所以 `--after/--before` 圈定的必然是一个**连续区间**：二分出
上下界，把这段整体前移到分配起点，返回缩短的切片。无过滤时零成本（旧实现无论
如何都会复制一遍并重新 append）。

前移而不是直接返回子切片，是因为调用方 `delete(filtered)` 要求指针落在分配起点上
（与既有的 `--max-count` 截断同一个约束）。

### 7. 退化阈值

- 每分区至少 `MERGE_MIN_PER_PART = 65536` 条才起线程（线程创建+销毁 50–80 µs，
  低于这个量级时固定开销吃掉收益）；
- 分区数上限 `MERGE_MAX_PARTITIONS = 16`；
- `threads ≤ 1`、数据量不足、只有 0/1 个列表 → 走串行分支，结果完全相同。

小文件因此与旧版等价：不新增线程、不新增分配。

## 结果

64 MiB 稠密（8 388 670 条命中）：

| | 旧 | 新 | 倍数 |
|---|---|---|---|
| merge 阶段 | 281.3 ms | 17.7 ms（4 线程）/ 11.9 ms（10 线程） | **15.6x** |
| filter 阶段 | 21.3 ms | 0.001 ms | 无过滤时不做 |
| 端到端 1 线程 | 0.38 s | 0.13 s | 2.9x（纯算法） |
| 端到端 4 线程（默认） | 0.35 s | 0.06 s | **5.7x** |
| 端到端 10 线程 | 0.34 s | 0.05 s | 6.8x |

线程伸缩也回来了：0.13 s（1 线程）→ 0.05 s（10 线程）。剩余时间几乎全在
worker 扫描（34.5 ms）与 merge（17.7 ms），两者都已接近内存带宽极限
（merge 读写各 134 MB / 17.7 ms ≈ 15 GB/s）。

稀疏（1 命中 / 64 KiB）与中等密度（1 命中 / 1 KB）：0.01 s，与旧版相当 ——
这两档由进程启动与读取主导，归并从来不是瓶颈，改动没有引入回归。

## 验证

- **逐字节一致**：74 MB `--dump` 输出 `cmp` 相同；5 组 `--after/--before` 边界
  （含空结果、单点命中、上界全开）与旧二进制逐个 `cmp` 相同；
- **与分区数无关**：`--threads 1/2/3/5/7/10/16` 的 dump 全部 identical（过滤开/关都测）；
- **目录扫描**：`-r -n "proc" src` 的 3899 行 stdout 与旧版相同；
- `search` 新增 3 个用例（含"与旧算法逐条比对"的等价性测试，40 轮随机 +
  大量相等偏移 + `pat_len` 区分来源列表）、`engine` 新增 2 个（48 万条 × p=1..8
  的并行/串行比对 + 边界情形）；
- 全量：145 单测（原 140）+ 内建自检 + 78 golden + run2 34 + run3 56 + 护栏全过。

## 取舍与遗留

- **输出确定性来自切分，不来自"单线程"**。若将来改成"线程各自 append 到共享
  数组"，就会同时失去确定性与负载均衡 —— 这是本 ADR 最该被记住的一条。
- **没有做 count-only 的惰性物化**：`-c` 且无 `--dump` 时其实只需要条目数
  （= Σ `upper_bound(before)` − Σ `lower_bound(after)`，O(K log n)），整套归并
  可以完全跳过。预计 dense 能到 ~0.03 s。但这会改变 `scan_region_parallel`
  的返回契约（计数 vs 切片），牵扯 `--max-count` 截断与落盘分支，收益大但面也大，
  单独做。
- **K 很大时的下一步**：堆的每层一次比较、每次比较一次 cache miss；K 到 64 以上
  时二阶段两两归并（扇入 log K 轮、顺序访存）通常更快。当前 K = 32 且已带宽受限，
  暂不引入。
- 阈值 65536 / 16 是按本机实测定的经验值，不是常数真理；换机器需要重测。
